PhantomBladeRuntime — Steam build 26367565 / CL-302256_JKS-17280

Runtime package version: 1.6.0. All script mods use isolated namespaces and run
after MainStart; no script-overriding PAK is generated. Supports chunked map geometry
within a bounded disk inventory; older packages retain an installed newer loader.
Version 1.6.0 adds DamageMonitor to the loader inventory and bootstrap dispatch.
It retains the StorySkip dispatch and asynchronous map surface bridge from 1.5.0.
Installing an older mod package retains this loader and its DamageMonitor support.

This loader forwards the system version.dll API and installs five MinHook hooks
from a startup worker. It uses the game's existing PuerTS environment after
FJsEnvImpl::Start("MainStart") returns, before gameplay objects request mixins.
The Start hook is enabled before fingerprinting scripts. MainStart waits for the
worker to finish the inventory and enable validation hooks; initialization failure
releases it without bootstrapping mods. Atlas scanning no longer delays this hook.
It does not alter any original game script or the executable on disk.

LoadModule and ExecuteModule call the byte validator after loading the file.
EvalScript calls the source validator with the path in argument 4 and source in
argument 1. Original modular.js adds the standard CommonJS wrapper to source.
Only the thirteen owned namespaces (Runtime, Sprint, Map, InfiniteTalisman, QuickActions,
Targeting, Loadouts, KillingIntent, EquipmentSync, Teleport, DocumentRecovery,
MemoryFlowers, StorySkip), fingerprinted
on the worker, can pass our validator;
all other paths retain the game's original validation. Contents must match the
startup SHA-256 fingerprints and lengths for bytes or source. Scripts are UTF-8,
at most 16 MiB per module, 512 MiB combined and 32768 modules. The combined limit
counts on-disk geometry chunks, not resident JavaScript. The worker fingerprints
one file at a time and releases its source buffers; PuerTS loads modules on demand.
Package builds and installation check the same limits before changing game files.

PE timestamp, image size and all seven entry signatures must match before hooks
are installed. Future builds require an explicit ABI review, even if scripts are
unchanged. Native diagnostics are written by the startup worker, not callbacks.
START_GUARDED means the early Start hook is installed; READY means the inventory
and validation hooks are ready. BOOTSTRAP_RETURNED means ExecuteModule returned,
not proof that gameplay functions work. Own-mod console messages are copied to a
bounded queue (128 entries, 4096 UTF-16 characters each) and written by the worker
to loader.log, capped at 2 MiB per launch. The game's encrypted log stays intact.

Build: native\runtime\Build.cmd (Visual Studio x64 C++ tools, CMake and Ninja)
Uses the existing vendored MinHook sources and license in the arena native tree.
The surface worker uses vendored miniz 3.1.1 inflate (MIT license).

Map surface bridge / 楼层数据异步接口
puerts.loadModule("pbz-map-surface-v1/<owner>/<world>/<x>_<y>") queues or polls
one data chunk. "~" means pending/backpressure; "!SURFACE_*" means failure;
success is the base64 encoding of the decompressed binary arrays, never JS source.
The game's shipping build has no general native-addon loader or binary LoadModule
return path, so the bridge reuses its existing UTF-8 string conversion. Only this
reserved prefix is intercepted; ordinary module loading and validation are unchanged.
The callback copies ready results; all disk reads, zlib inflate, SHA-256 checking
and base64 encoding run on the existing worker. At most four requests are retained,
each limited to 1 MiB compressed and 1 MiB decoded. Closing an atlas sends
"pbz-map-surface-v1/<owner>/cancel"; completed/cancelled chunks are released.
Only validated world and tile identifiers beneath PhantomBladeMap/surfaces are
read, and linked paths are rejected. PBS1 headers bind lengths and SHA-256 to the
raw float32/int32 arrays. The 48-byte header is followed by an independent zlib
stream. A 12-byte decoded header gives the three array lengths (element counts).
JavaScript retains an LRU of at most 32 chunks / 8 MiB, with no module-cache copies.
新接口只传递数据；后台读取、解压和校验，地图每次更新最多接收一个分块。
此接口尚未进行游戏内验证；编译及打包过程的全量无损回读校验通过。
