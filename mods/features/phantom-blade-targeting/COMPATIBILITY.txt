保留边界 / Preservation boundaries
- Inherited PuerTS mixins create separate handler/validator classes and instances.
  Original blueprint classes and other characters are not modified.
  Each replacement handler has its own validator. Initialize temporarily resolves
  it through the validator map, which is immediately restored in finally. Existing
  gun/special handlers therefore keep their original validator instances.
  Bow replacement preserves its TargetingHandlers array index and tag. Native
  GetTargetHandler (RVA 17fe0320) uses the cached tag-to-index map to read that array;
  attachment checks the registered replacement through this native getter.
- New attachment waits for an unlocked player with no special handler/action.
  Special handlers (gun/other aiming, combat snap, soft focus, continuous execution, perfect
  dodge and underwater targeting) and defense/dodge/execution tags bypass policy.
  Their validators, target changes and temporary locks keep native behavior.
- Only the active normal/bow changer receives input parameters. Parameters are
  restored on mode changes and during special actions, cinematics,
  ignored-look input and pause. Restoration compares native float32 values.
- No SetLockTarget/StopLockTarget hook, periodic target replacement or automatic
  forced return to an old target. Scripted lock requests remain native so that
  temporary combat locks are not suppressed. Stability here covers input churn
  and intermittent occlusion, not every scripted camera/lock request.
- Unknown classes/missing methods or changed component ownership disable this
  mod's policy. Active native validator delegates are not torn down on detach.
  Object identity, native Initialize results and changer fields are checked.
