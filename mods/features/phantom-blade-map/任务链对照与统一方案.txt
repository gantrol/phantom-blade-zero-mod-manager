一、结论与本轮范围

当前 QuestChainCatalog.js 是三条任务的导航摘要：3 个任务、7 个展示步骤、5 个奖励引用。
它不是游戏完整任务图，也不能直接作为修复存档的依据。
统一方向是“原生事实目录 + 当前存档状态 + 导航展示”，各自保存自己的语义。
地图、物品收集和支线修复可以引用同一份事实目录，但修复写入保持独立。
P0 状态修正、地图联动和分级提示已实施；按版本生成事实目录已完成方块与剑阵样本，完整覆盖与运行时接入仍待实施。
第四节保留审计时的问题记录，第八节说明当前实现。原审计 JSON 的 4 个奖励引用为历史数量。

证据文件：design/quest-source-audit.json。
其中保留 12 份相关流程资产的 318 个节点、输出连线及导出文件 SHA-256。
这是来源审计材料，不是可直接装入游戏的任务目录。

方块

  原生有两条合法入口：
    A. 先与渔夫交谈，启动 S1；两个获得方块标签满足后，经 S2 交谈、发放 R_06033，再启动 1。
    B. 已集齐方块后首次交谈，经 IsTagExist_C 另一出口发放 R_06033，直接启动 1，不经过 FinishQuest(S2)。
  B 路径的 BeginQuest(1)：6E92D60B-480B398B-B2BCAF87-8BE934A5。
  A 路径的 FinishQuest(S2)：B0715AC1-4271192E-F6745DBE-BA07EE2B。
  幻鬼流程先交付 AC_ShachiWeapon_1、AC_ShachiWeapon_2，再发放成品，最后结算分支 1。
  因此“渔夫引导步骤已满足”可以成立，“原生 S2 已完成”却不一定成立。
  after 不能同时承担展示顺序、强制前置和原生完成证明三个含义。

魔教之女、剑阵战斗、七星剑阵收集
  原生身份分别存在：
    /Game/PBZstory/PBZQuest/Simple/MoJiaoZhiNv.MoJiaoZhiNv_C
    /Game/PBZstory/PBZQuest/Collect/QiXingJianZhen.QiXingJianZhen_C
  BPF_NvJianKe_GeShe 启动传闻 S1；BPF_HongYiNvJianKe_Leave 设置荡绳离开标签并启动分支 1。
  BPF_JianZhenDeath 中，战斗结束标签与任务结算是不同节点：
    E043EB3A-43A7E3BA-265D17A3-BF2010E2 设置“剑阵.完成任务”“显示记忆之花”等标签；
    7FCFB62E-40F9A917-BCE58FA7-FFAEA380 发放武器 JianKeZhaoJiLing；
    61CE7532-4E07B762-9F85258F-3AB8E66F 发放 K_03004；
    关闭奖励窗口后，14D51A80-44DD3540-12A639B0-1D0E3A10 执行 FinishQuest(MoJiaoZhiNv,1)。
  当前导航奖励表漏列了该武器；它只能称作部分奖励引用。
  F_03008 来自独立的 BPF_JianZhen_Memory_0。门条件是“显示记忆之花”且没有“击杀红衣女剑客”，
  未要求 MoJiaoZhiNv/1 已完成。当前 QuestChains.entries 又要求展示步骤 completed 才给奖励定位，
  因而在战斗已结束、任务尚未结算时，可能把原本可领取的花挡住。
  同一剧情可以在界面中关联展示，但必须分别显示战斗、传闻任务、收集任务和每个奖励状态。

失败、受阻与错过
  三面混沌流程存在显式 FinishQuestGroup(Failed=true)，也存在正常完成出口。
  Native Failed、临时 Blocked、等待事件、另一条分支已选、来源未加载，不是同一种状态。
  当前 branchState 把 Failed 统一显示为 missed；read/obstacle 又把一个展示前置的 missed 传播到后续。
  这种推导不能覆盖游戏实际处于 InProcess 的分支，也不能证明奖励已永久不可领取。
  “已错过”只用于具备明确失效证据的具体路线或奖励；原生失败保留“失败”，未知保留“待确认”。

游戏中的书信与读物
  DocumentSources 已记录“物品 ID → 流程/奖励 GUID → 场景来源”；这可以与任务图联接。
  例如 R_06033 来自渔夫两条交谈路径，但同属 Book_03 并不意味着整本书就是方块任务链。
  给出物品（GiveItems）、获得物品（GetItems/LootItems）、作为线索、仅有剧情关联，应分别标注。
  共享 NPC、同属一本书、在同一 FlowAsset 出现，均不足以单独证明任务前置关系。
  已获得、当前持有数量、原生读物页可见性也应分开；交付后的数量为零不能抹掉获得记录。

五、统一的数据结构与状态解释

A. 原生事实目录（构建时生成）
  questId：完整生成类路径；branchId：questId + 原生分支 ID；taskId：带所属分支的原生任务 ID。
  flowId：完整资产路径；nodeId：flowId + NodeGuid；itemId、actorId、targetPointId 沿用游戏 ID。
  读取任务资产中的 State、Branch、Task、DestinationState，以及流程节点的输入/输出和条件。
  分别保存 activates、finishes、fails、requiresAll、requiresAny、consumes、grants、locates 等已证实关系。
  带观察/阻断标签、反向条件、监听任务状态、输出 pin；保留无法解释的原生节点及 unknown 标记。
  每项关系附 gameBuild、资产散列、导出散列、定位依据、证据节点和核验级别。
  不以短文件名作全局身份；不按分支编号排序来生成前置关系；不把 ObjectPath 的导出序号当稳定 ID。

B. 当前存档状态（运行时只读）
  nativeProgress：原生 Quest/Branch/Task 的状态，保留原始值及明确映射。
  availability：当前是否可交互、缺少条件、来源未加载或未知。
  acquisition：本周目是否获得；amount：当前数量。二者分别读取。
  routeOutcome：某条具体路线是否失效、另一路线是否仍可行；不能传播成整个任务失败。
  指导步骤满足只是 derived 状态，不能回写或替代 nativeProgress。
  QuestList 中没有某项、场景中暂时没有 NPC，都不能直接推出“未接”或“已错过”。
  地图和 HUD 共用有版本的数值快照；读档、角色/周目变化时失效重读，不另存一套完成日志。

C. 导航展示（少量人工整理）
  只定义分组、简短标题键、显示顺序、隐藏后续剧情，以及需要展示的事实节点引用。
  保留“任务列表 → 步骤 → 定位/追踪”的现有界面；必要时在同一分组中显示相关独立任务。
  displayOrder 与硬性 requires 分离。原生当前可做目标优先，历史摘要不能把它改成已错过。
  无位置时仍展示条件；有可靠位置才允许定位。奖励定位读取奖励自身的来源条件。
  自动接续使用已证实的后继或原生追踪结果；并行/互斥选择不依赖数组顺序。

六、现有代码如何复用

ResourceExport.cs：继续承担离线导出，补齐游戏版本、资产散列和任务资产导出。
CollectionGates / CollectionFlow：继续读取原生执行门、Choice 有效性和物品条件。
  compile-collection-gates.cjs 当前将 BeginQuest/FinishQuest 等视作奖励路径的经过节点，
  这是它的用途边界。任务图编译器必须把这些节点保留为事件效果，不能直接照搬 pass 集合。
CollectionRequirements：作为已知失败原因的解释层，避免升级成另一套手写任务状态机。
Documents / CollectionState / SourceState：共用物品身份、获得记录、名称和来源判断。
QuestObjectives：逐步改为统一事实目录的地点引用，避免与任务目录、场景目录重复维护坐标。
QuestChains：只组合 nativeProgress、availability 和展示规则，不再沿 after 强制推导原生状态。
支线管理器：共用稳定 ID 和诊断证据；资格检查、备份、写入和回读仍由原有修复代码负责。
  修复方案是受约束的另存操作，不是游戏正常任务边，不进入地图的自动追踪逻辑。

  对未支持的节点保留未知；原生流程可以回环，不能把它强行裁成无环的直线任务链。

P2：让地图、收集目录和修复诊断读取同一事实来源。
  可用仓库级 data/quests/<build>/ 存原始事实与覆盖元数据；构建分别输出地图 JS 与管理器 JSON。

  文档由覆盖报告更新数量和核验状态，避免多个说明文件手工维护不同的“全部完成”结论。

检查限于静态结构、来源引用、模块语法及构建完整性；不自动新增测试代码、操作游戏或修改存档。
真实状态组合和 UI 表现仍需用户另行安排实机验证，不以静态检查代替。

八、2026-11-08 实现说明

QuestChains 保留 nativeProgress 的状态、原生枚举值，并单独保存 derived 满足证据。
方块的后继分支只证明渔夫引导步骤已满足，不把 S2 写成原生完成。
展示数组只负责排序；requiresAll 只解释未激活步骤的条件，不改变原生进度。
Failed 保留失败；missed 仅由具体目标的明确失效标签给出，不沿展示顺序传播。
剑阵结束标签只提示尚待结算，不把任务进度改成未知；原生可见目标优先于补充导航。
奖励复用 CollectionState，并为读物引用 DocumentCatalog 的原生获得节点。
获得记录与当前数量分开，奖励定位使用来源可用性，不额外要求叙事步骤完成。
补入 JianKeZhaoJiLing，使用 ShaqiWeaponInfos 的获得记录。
任务暂不在加载列表时暂停地点指引并保留待确认，不据此宣告完成或失败。

提示等级使用稳定值 explore / hints / guide，默认 hints；游戏和管理器设置共用 schema 7。
探索：只记录已完成步骤与已领取奖励，不增加任务目的地，不接续 MOD 任务指引。
提示：显示原生已激活/已发生的步骤和已显现奖励，隐藏后续步骤及总步骤数。
攻略：展示已知全部步骤、条件和奖励；未激活目标仍不可追踪。
任务面板可直接切换；筛选面板任务页支持手柄选择。原生地图的标记和操作保持可用。
地图上的当前任务目标可一起显示，焦点任务以外的新增标记淡显，聚合不混合不同任务。
步骤选择定位地图及楼层；原生任务标记首次确认打开任务链，再次确认切换追踪。
已完成任务仍有未领取/待确认奖励时，提示和攻略模式的剩余列表继续保留它。
本次不扩展任务覆盖、不提升旧来源的版本核验级别、不增加修复存档入口。

复核修正：仅已探索路线共用分帧检查，投影额度耗尽保留待查游标，不判作迷雾；
原生可达终点仍优先，离线地形不延长原生部分路线。真实迷雾处只保留已核实路段。
HUD 保留已收集目录项，关闭仅未获得后恢复显示；周期刷新只更新收集状态。
小地图铃铛与分层地图一致，作为地标不受物品分类及仅未获得筛选影响。
前置错过不覆盖原生进行中、记忆之花按自身领取条件导航两项继续沿用上述修正。
本轮仍只进行静态核对、语法和构建检查；11 月 5 日旧构建日志不作为当前运行证据。

十、2026-11-09 离线事实目录样本

目录保留原生执行连线和 pin、任务状态/分支/目标、标签引用、交付/奖励、场景层与生成器效果。
