分层地图交互优化方案
2026-11-14 · 状态：方案，尚未实施下述新增交互

结论
先把“看哪层、选中了什么、确认会做什么、怎样回去”统一起来，再增加功能。
保留已有平移、鼠标位置缩放、平滑定位、点位列表和原图入口，复用现有组件与风格。
本次依据源码审查、用户反馈及公开游戏无障碍指南；没有进行游戏试玩、UI 交互验证或用户访谈。

一、现状与问题
1. 楼层：已有上下层、玩家层/目标层跳转；但切层遍历整个世界的楼层。
   显示层、玩家层、目标层分散在标签和条件提示中，切层时还可能重新定位。
   涉及 Session.js 的楼层动作及 MapPane.js 的 update/layoutToolbar。
2. 返回：剧情连接和跨层连接会移动地图；没有与此对应的浏览历史。
   handleBack 在分层图中会切回原图，和“返回刚才位置”的预期容易冲突。
3. 确认：点位选择、再次确认追踪、已激活铃铛操作、连接浏览共用入口。
   Session.js 中任务确认与地图中心确认也有优先级竞争，需要明确当前焦点。
   Entry.js 会忽略按住达到 500 ms 的鼠标释放，即使没有拖动；慢点击可能无响应。
4. 信息：已有重叠点轮换/聚合、前置条件提示和点位列表；不能把这些作为待新增功能。
   更需要区分“已选中”“正追踪”“另一层”“条件未满足”，并解释空列表原因。
5. 布局：本轮已修复窄区域工具栏换行，但极窄区域继续缩小按钮仍不利于操作。
   小地图固定为视口宽 23%、最多 280 逻辑像素，没有用户大小调节项。
6. 自动收集：本轮已修复失败目标反复插队；目前等待提示仍不能说明扫描进展。

二、第一批：可理解、可返回、可确认（优先实施）

A. 明确楼层与浏览状态
顶栏固定显示“区域 · 正在查看的楼层”，旁边提供“我的位置”和“追踪目标”。
玩家层和目标层用独立标记表达，不再轮流占用同一个状态提示。
点击楼层名展开楼层列表，按高度排序；当前视野附近有内容的层优先展示，其他层可展开。
未知高度显示“楼层未确定”，不猜测层号；区域/地点名优先使用已有语言资源。

手动切层默认保留地图中心和缩放；该位置在目标层没有图面时显示“查看此层范围”按钮。
只有用户选择点位、连接或“我的位置”时才明确移动地图。
自动室内切换继续默认关闭；启用后手动操作优先，关闭地图后再恢复自动判断。
自动切换和用户保存的视图偏好分开维护；自动识别不能覆盖正在浏览的层。

B. 给井口、井底和剧情传送提供可逆浏览
选择连接后显示简短动作卡：来源、去向、单向/双向、已知前置条件。
三人偶水井示例：“井口 → 井底 · 单向”，主按钮“查看井底”。
只查看地图另一端时不改变玩家位置；返回动作叫“返回井口视图”，避免暗示可以原路走回。
同一连接的编号保持一致，配合箭头和端点名称；不能只靠颜色区分两端。
来源信息不足时使用已有区域与楼层名称，不编造房间名、触发条件或步行路线。

浏览历史保留最近 8 次显式跳转：世界、楼层、中心、缩放、选中点。
自动更新和每次拖动不入历史；历史只在当前打开地图的会话内保存，跨存档清空。
返回视图恢复位置与选择，不撤销追踪、完成状态或用户刚修改的筛选。
返回键顺序：关闭展开面板/弹层 → 退出点位动作卡 → 返回上一浏览位置 → 关闭地图。
原图/分层只通过明确的视图入口切换；没有自定义上下文时交还游戏原生返回行为。

C. 统一选择和动作
鼠标单击或手柄确认先选点；选中后在同一位置展示明确动作：追踪、取消追踪、查看另一端、铃铛操作。
重复确认执行当前可见的主动作；铃铛动作继续走原生可用性判断与确认流程。
地图、列表、工具栏、弹层各自拥有焦点；一次输入只交给当前焦点，禁止任务列表抢走地图确认。
提示显示当前实际绑定及设备图标，复用 Controls；键鼠、手柄都能从列表完成点位操作。
点击/拖动以移动距离和按下位置判定；无长按功能的普通点击取消 500 ms 截断。
拖动越界松开、关闭地图、切换输入设备时取消悬空按下状态。

建议布局（示意，不是实现）
  [原图 | 分层]  区域 · 地下 1 [选层]     [我的位置] [追踪目标]
  [收集 / 任务 / 筛选，可收起]            地图
                                       [选中点：名称、楼层、条件]
                                       [追踪 / 查看另一端 / 铃铛动作]
  [当前焦点对应的确认、返回、缩放提示]    [返回上一位置]

三、第二批：减少遮挡和等待感
1. 收集/任务列表和筛选共享侧栏空间，窄视口改为可收起面板。
   先换行、再收起低频操作；图标点击区域不跟着地图缩放无限缩小。
   放大文字时重新排布，控件和命中区域共用布局结果，保持原有视觉风格。
2. 当前层图标为主，其他层默认不叠满地图；追踪目标在其他层时保留明确入口。
   聚合点展开后暂时固定选择，缩放/移动不会突然换成附近另一个点。
   列表与地图共享选中 ID；定位列表项目时同步区域、楼层和相机。
3. 空列表区分“本层没有目标”“被筛选隐藏”“尚未确认位置”，提供相应恢复入口。
   对剧情任务保留整条任务链入口，同时强调当前可行动的下一步。
4. 自动收集显示“正在检查附近目标”“本轮已检查 N 个”“暂未找到可达目标”。
   提供暂停和跳过当前目标；短期失败不永久判为不可达，移动/解锁/新一轮时可重查。
   “跳过”与“已完成”分开；跳过仅作用于本次自动选择，不改存档收集状态。
5. 小地图增加小/中/大三档，中档保留现在的大小；位置与透明度放在同一设置组。
   小地图继续跟随玩家，大地图自由浏览；“我的位置”总能回到玩家当前层。
6. 首次进入只显示一条可关闭的就地提示，说明选层、回到自己、连接浏览入口。
   帮助可随时重开；不强制弹教程，也不在普通使用流程展示提取器、缓存等实现信息。

四、实现边界与性能
第一批建议顺序：浏览状态/返回历史 → 楼层控件 → 焦点与统一动作。
主要修改 Session.js、MapPane.js、PointHint.js、Entry.js、View.js、Locales.js。
第二批再涉及 FilterPanel.js、HudRuntime.js、Settings.js 和管理器地图设置。
新增状态使用稳定标识符，显示文字同步维护简体中文和英文；控件复用并按变化更新。
不为指针移动、拖图和选层新增同步寻路；几何和贴图继续按区域加载、复用缓存。
资源压缩只能减少文件/纹理负担，实际掉帧改善需要运行时数据确认，不能由包体缩减推断。

路线规划单列后续任务：当前仍是目标标记、直线距离、高差和自动选点。
剧情跳转连线不代表可步行路径，楼层切换也不能宣称已解决寻路。
先确保入口/出口、单向性和条件可信，再评估包含剧情连接的可达图与路线规划。

五、后续验收场景（实施后、允许交互验证时执行；本轮未执行）
1. 室内自动进入分层图后手动选择分层，离开室内及重新开图仍符合保存偏好。
2. 三人偶井口查看井底，再返回：区域、层、中心、缩放恢复；追踪状态不变。
3. 连续浏览两个跨层/跨区域连接，返回顺序正确；单向连接没有反向可走的暗示。
4. 手柄选任务后把焦点移到地图铃铛，确认只操作该铃铛；键鼠慢点击也能选中。
5. 窄视口及最大文字缩放下，控件不重叠侧栏，命中区域与画面一致。
6. 目标被筛选或位于别层时能解释原因；列表、地图能互相定位且不会改变当前追踪。
7. 多个近处不可达目标与一个远处可达目标并存，最终选到可达点；等待过程有可理解反馈。
8. 记录开图、切层与玩家移动的帧耗时及纹理加载次数，再与当前版本比较；不预设提升百分比。

六、调研依据
Microsoft XAG 112：一致的导航、可预测焦点、返回路径，以及地图的列表操作替代方式。
https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112
Microsoft XAG 107：提供不同输入方式，避免不必要的速度/时限要求。
https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107
Microsoft XAG 103：关键状态同时使用文字、符号等线索，避免只依赖颜色。
https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103
以上指南用于设计依据，不构成本 MOD 已满足完整无障碍标准的认证。

English scope summary
This is a proposal based on source review and public guidance, without in-game testing.
Phase one clarifies viewed/player/target floors, adds reversible map browsing, and unifies
selection, focus and contextual actions. Phase two improves narrow layouts, filtering,
auto-collection feedback and minimap sizing. Route planning remains a separate project.
