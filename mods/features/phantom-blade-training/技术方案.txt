一、确定采用的结构

采用 UE4SS C++ 原生插件，配合游戏内 UMG 界面和独立 UI 资源包。
用户仍从 Steam 正常启动原游戏，加载器在游戏进程内载入演武场。
运行时使用 C++；不编写 Lua，也不沿用上一版 JavaScript 战斗控制代码。

发布物的职责：
1. Mods/PhantomBladeArena/dlls/main.dll：入口、会话状态、战斗生命周期、存档保护。
2. 演武场自己的 PAK/IoStore 资源：需要新增的 UMG 资源、语言资源与战斗目录。
3. 本 MOD 目录使用 enabled.txt 启用标记；安装与卸载只处理本 MOD 的文件。

游戏原 EXE、原资源包、其他 MOD 保持原样。无需游戏副本、硬链接目录、启动参数或日常启动脚本。
本机已有 UE4SS；本 MOD 使用现有加载器，不替换 dwmapi.dll 或 UE4SS.dll。
安装器即便后续提供，也只负责一次性安装，不能承担运行中的战斗逻辑或启动游戏。

二、选型依据与已核实事实

本机 UE4SS 日志记录：v3.0.1 Beta #0，Git SHA cdbc0b66，Game__Shipping__Win64 (MSVC)。
日志中的真实游戏进程目录为 Steam 原安装目录下 platform/steam。
UE4SS 官方提供 C++ MOD 接口和 dlls/main.dll 的加载约定。
本地已有 CppUserModBase 头文件及导入库，但仍须确认它们与上述运行库的 ABI 一致，不能只凭文件存在判断兼容。

原系统菜单有 TabList、VisibilitySwitcher、TabToSwitcherIndexMap；可以据此定位插入位置。
Boss 资产目录和地图中实际放置的生成器可以离线读取。
这些事实仅能证明接口和资产存在，不能证明完整战斗、入场点或多阶段重置已经可用。

三、界面

保持已经确定的需求与布局：原系统菜单“系统”后新增同级“演武场”。
界面通过游戏的 UMG/CommonUI 生命周期创建、导航和销毁，复用原字体、控件风格与输入动作。
不用独立窗口、外部网页或调试覆盖层替代游戏菜单。
新快捷键继续待定，不写死 F 键，不改变原战斗按键。

C++ 插件在系统菜单创建后挂接演武场，在菜单销毁时解绑。
界面只提交意图并展示实际结果：选择对手、选择场景、开始、继续、重置、锁血、退出。
“当前练习”和“待开始选择”由独立的会话状态维护；点击开始不等于启动成功。
只有场景、玩家和完整战斗均就绪后，才切换到“练习中”。

四、练习会话

原游戏会话 → 保存返回状态 → 建立练习会话 → 场景准备 → 战斗准备 → 练习中。
重置重建当前战斗的初始状态；退出恢复进入演武场前的状态。
所有引擎对象操作在游戏线程执行；跨地图后重新取得当前世界与角色，旧对象引用及时释放。
资源准备使用加载完成与角色初始化事件，不用固定延迟假设载入成功。

场景：复用原地图资产。默认场景必须是这场 Boss 战的实际战斗区域。
进入练习时隔离剧情推进、奖励结算和与练习无关的触发逻辑；不对原游戏会话调用全局“终止所有剧情流程”。
练习控制器只管理它接管的战斗对象，退出时完整释放。

对手：按“完整战斗”整理目录，记录关联阶段、同场敌人、原场地、开战与重置条件。
普通敌人类名、图鉴标记、生成器坐标都不能单独充当一场完整 Boss 战的定义。
已提取的五个候选对手仍是调查材料，不沿用“已经支持五场完整战斗”的结论。

重置：清理本轮战斗对象与临时效果，恢复玩家位置、装备和本轮初始资源，重建完整战斗。
开局与重置补满生命、杀气、终结技能等实际可用的能量槽。
锁血：在生命值变更进入死亡判定前处理，锁定玩家生命；关闭时恢复正常伤害逻辑。
不能把“保留最低生命值”效果或定时回血冒充锁血。

五、存档保护是核心功能

本机原生 SaveVeto 只是一层限制。原游戏代码明确说明 ForceSave 可以绕过否决，账号记录也有独立写入路径。
因此，“调用 EnterSaveVeto”不足以声称练习不会影响主存档。

由 C++ 会话模块负责核对并控制以下路径：
普通保存、强制保存、异步在途保存、账号级保存、退出游戏保存，以及平台成就/统计提交。
挂接应落在实际原生写入调用链上；只拦脚本调用或 Blueprint 事件无法覆盖原生直接调用。
进入练习前须确认在途保存已经结束；练习期间的保存请求采用原生一致的拒绝/取消语义。
不能假报保存成功，也不能把练习期间积压的请求在退出后再写回主存档。
异常退出时主存档应保留练习前状态。主动退出时先恢复原会话，再恢复正常保存。

具体挂接点、完整覆盖范围、恢复顺序目前尚未验证，属于新实现的首要工作。
在这些条件闭合之前，不向原存档安装可开始战斗的发布包。内部菜单构建不开放战斗。

六、实施顺序与完成依据

1. 固定加载器 ABI 与游戏版本；完成真正的原生 DLL 入口和生命周期处理。
2. 在原菜单插入可进入、可返回、可重复打开的 UMG 演武场页面。
3. 闭合保存请求控制与返回状态恢复，先于任何跨场景战斗接入。
4. 核实一场完整 Boss 战，接通入场、满能量、结束、重置、锁血、退出。
5. 按相同证据要求扩充战斗与场景目录，处理多阶段和同场多敌人。

编译成功、资源包可读取和脚本语法检查都不等于游戏内功能完成。
游戏内验收须实际覆盖正常 Steam 启动、反复开关菜单、战斗与重置、主动退出及异常退出后的存档状态。
当前用户规则禁止自行进行 UI/实机操作；未取得相应明确指令前不执行这些验证，不标注为通过。
