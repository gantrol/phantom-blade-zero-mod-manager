一、入口与主要流程

管理器增加独立的「一键配装」MOD，复用 native/runtime 加载器。游戏内入口放在角色装备页，和主武器、影之武装、饰品、药品相邻；不绑定一个容易与其他 MOD 冲突的新全局热键。管理器开关同时控制配装入口及装备列表搜索。

装备页右侧打开配装面板：

  配装                 [搜索名称或效果              ×]
  [当前进度] [全部预设] [我的配装]
  用途：[推图] [生存] [持续] [破盾] [绝技] [元素／机制]
  ┌────────────────┬─────────────────────────────┐
  │ 二周目 · 推图   │ 主武器：绝影 → 别离残钩       │
  │ 物理持续        │ 影之武装：铁拳套、虚空华扇     │
  │ 反制破盾        │ 饰品：逐槽显示当前 → 目标       │
  │ 两格绝技爆发    │ 药品：保留当前                │
  │ ……             │ [ ] 同时切换药品              │
  │                │ 可应用／缺件／铸魂未完成       │
  │                │ 输出循环、必要条件             │
  └────────────────┴─────────────────────────────┘
  [保存当前] [撤销上次换装]                 [一键配装]

选中预设立即显示完整差异，不弹逐槽确认。点击「一键配装」才修改装备。条件不满足时禁用按钮，并列出具体缺件、槽位、铸魂或原生换装限制。没有可用预设时保留当前装备并展示下一阶段缺件。所有推荐都是条件推荐，不标注「最高伤害」或虚构 DPS。

我的配装保存稳定物品 ID 与槽位，不保存强化、铸魂、打磨、轮回或药品次数的可写副本。允许保存当前、重命名、覆盖、删除；删除仅影响 MOD 配置。缺件或升级后的名称变化不破坏预设。

二、按进度内置配装

原有 19 套：6 套一周目阶段配置、研究中的 12 套二周目用途配置，以及依据装备描述新增的 1 套生存配置。具体 ID、条件与优先序见 data/presets.json，展示文案见 locales/zh-CN.json 与 locales/en.json。

一周目：
1. 溪谷双刃：黑伤双刃＋长形黑伤；巨凶斧＋羽弓。
2. 伏击之林：黑伤双刃＋痴者残剑；铁拳套＋巨凶斧。
3. 双钺残钩：天煞双钺＋别离残钩；铁拳套＋巨凶斧。
4. 重击成型：沿用双钺残钩，取得残破容器后调整饰品。
5. 拳扇循环：铁拳套＋虚空华扇，取得粗糙煌心后进入此阶段。
6. 后期推图：绝影＋别离残钩；铁拳套＋虚空华扇；傩面、煌心等构成六槽目标。

二周目：推图、稳守续航、物理持续、反制破盾、强拆盾、雷弱点、火伤配合、冰缓／水雪、混沌／幻体、毒弱点、两格绝技爆发、单格绝技循环、骑乘阶段。

新增「稳守续航」（ngplus_survival）：绝影＋别离残钩；拙壁盾＋虚空华扇。三件生存饰品为古甲残片·极、慈母护符·改、坚岩护腕·改；三件辅助饰品为浑源经脉仪·极、沉香念珠·改、百相傩面·极。药品建议济生神药＋苦叶露，仍默认保留当前药品。此套为本次根据 rechecked-source-catalog.json 组合的设计建议，不是原研究中的既有方案或实测最强生存结论；sourcePointer 为空字符串，按 JSON Pointer 表示该装备目录根节点。

该方案按普通打磨上限展示：古甲最高减伤 40%、坚岩在自身未破防时减伤 20%、慈母在自身被破防时回复 20% 生命；浑源完美格挡／闪避窗口 +25%、沉香自身破防状态恢复时间 -30%。古甲的计算函数将生命比例 90%～10% 映射为效果比例 1～0 并夹取，因此达到 90% 生命即可获得最高效果。苦叶露满级减伤 40%、持续 25 秒；华扇 5 级解锁场域减伤 30%，必须在场域内。慈母不是击破敌人后的回血，也不等于免死或复活；不能在未核实致死与回血时序前作此保证。傩面这里只计华扇的暗源减耗，不假定同样作用于拙壁盾。拙壁盾持续举盾和受击都会耗杀气，杀气归零会破盾；10 级开始有举盾减耗，25 级加快举收盾。

减伤运算已按本地 Build 26367565 可执行文件核对：编号 1 是 MultiplyAdditive，编号 4 是 MultiplyCompound；0x144D1C52A 对编号 4 的各效果执行 mulss，0x144D1C584 将该乘积代入属性结果。古甲物理、坚岩、苦叶露、华扇都使用编号 4；古甲元素使用编号 0 加上 -0.4，随后仍与其余三项连乘。因此古甲最高效果且未破防时，两饰品减伤为 1−0.6×0.8＝52%；再开苦叶露为 71.2%；同时处于华扇场域为 79.84%。这些是所核对物理／元素属性路径的静态结果，不包含真伤或另行结算的伤害，也不代表恒定覆盖。完整证据保存在 .local/ngplus-damage-26367565/survival-mitigation-audit.json 与 native-aggregator-mitigation.txt；尚未进行实机受击验证。

此版覆盖：承压前喝苦叶露、开华扇；被破防前靠古甲、坚岩减伤与操作窗口容错。失误被破防后坚岩失效，由慈母回血和沉香缩短恢复提供补救，古甲仍按实际血量计算。短举盾承压、杀气耗尽前收盾，空隙反击和补血；济生神药应急，不故意耗空杀气触发破防，也不为低血药效故意压低血量。苦叶露替换慈花甘露，以减伤兼持续回血承担第二药品槽。

选择取舍：三个生存槽分配给古甲、坚岩、慈母，同时覆盖减伤与破防回血；牺牲珍玩的 25% 生命上限。辅助槽用沉香替代弦音，牺牲杀气上限以缩短破防恢复。该选择针对兼顾常态承伤与失误补救的目标，不宣称所有敌人和操作习惯下最优。静心小葫芦的喝药解除破防、香薰药盒的治疗提升与霸体、百战魔躯的六秒无伤门槛、神奇刀鞘的换武短时保护也属于生存候选，但各依赖药品次数、操作机会、无伤间隔或换武条件，需占用同样最多三件的生存槽。元素或异常明确时再考虑对应抗性符。

其他已核对候选：神奇刀鞘·改换武后 3 秒减伤 40%；若用它替代慈母，三件减伤饰品加苦叶露、华扇的短时减伤为 87.904%，会失去破防回血，仍不能称为 100%。幻体灵药满级描述为 3 秒无形、无法被攻击击中；百战魔躯·改描述为连续 6 秒无伤后免疫下一次伤害，属于有条件的免伤手段。尚未确认可持续叠到 100% 的合法常规配装，不将条件免伤标成常驻减伤。

design/loadout-survival-v3.png 保留为界面布局参考，药品展示尚未同步本次苦叶露修订。v1、v2 保留为历史草稿：v1 漏了破防补救，v2 补上慈母但移除了坚岩，v3 保留古甲、坚岩并以慈母替换珍玩。仅通过物品 ID／槽位校验不能证明生存方案完整。慈母的静态依据：DT_Accessory 的 AC_BreakRegen 普通打磨描述，以及 GA_Accessory_BreakRegen_Lv2 的 Multiplier=0.2；沉香的静态依据：AC_BreakRecover 普通打磨描述。当前未实测触发时序、频率限制或极端伤害场景。

默认优先展示「当前进度」中可应用的推图预设，再按用途筛选；同用途采用 recommendationPriority 降序、ID 升序。进入新阶段只更新推荐，不自动换装。二周目可在「全部预设」查看并应用满足装备条件的一周目方案；cycleCountMin/Max 只控制默认推荐分组，不是装备权限。

进度依据依次为：读取成功的真实周目、实际持有物品、铸魂状态、饰品槽解锁、关键武器招式等级。地图或任务章节仅辅助显示，不以「到达某地图」代替获得奖励。周目读取失败时显示「进度未知」，仍可浏览全部预设；不得把未知当一周目。双钺／残钩最早获取路线未闭合，因此只使用「已取得」节点。

预设核心主武器及影之武装必须全部持有；requirements.milestoneItemIds 另指定阶段标志物。requirements.soulForgedItemIds 是该预设形态的硬条件。原研究的 12 套二周目源方案按四件武器均已铸魂整理；未铸魂版本须另存为自定义，不悄悄按同一名称套用。新增稳守续航只要求双刃铸魂为绝影，不把盾的铸魂反伤作为生存循环前提。强化和打磨属于 guidance 建议：不达参考值仍可换装，但必须显示实际等级和未解锁机制；不会自动强化或降级。

一周目饰品采用 priority：按 itemIds 顺序，从已拥有饰品中选择，最多占用当前已解锁槽位，且每类最多三件。槽位可用性复用原生 InitAccessory 的锁定判定，不仅按数量截取前 N 槽。选满后停止；缺失的优先饰品在差异预览中列出，不阻塞整套。空余槽优先保留合法的原有饰品；不能保留的槽位也列入差异，不静默清空。二周目 exact 配置要求六件齐全、六槽解锁；缺件禁止整套应用，可手动复制为自定义方案调整。

不要把研究中的输出假设写回角色：武器 30 级、普通打磨上限、满级药品、零轮回加成都是参考口径。保持玩家原有强化、铸魂、打磨和轮回值，也不改变天赋、属性、剧情、资源或物品数量。

三、一键应用与撤销

1. 只在原生装备页允许换装、无模态窗口及切图时准备方案。沿用 isLoadoutLockedByStory 等原生条件；演武场隔离会话内暂不开放整套换装，防止与临时配装及存档恢复相互覆盖。
2. 读取同一角色／存档／世界会话的背包快照，检查 ID、类别、持有、槽位、重复、饰品每类三件及召唤类影之武装最多一件。Summon 限制使用原生 ShaChiWeaponType，不能用内部战斗 Magic 标签代替。
3. 根据当前槽位规划完整最终状态。main 与 shadow 数组第一件表示期望主用、第二件表示备用；适配层将其映射到当前主用槽索引，不能把界面顺序误认成固定原生索引。药品数组按 bottom、top；饰品按预览中的实际槽索引映射。
4. 药品默认不参与换装。勾选后才检查两个药品的持有和重复；若任一待替换药品仍有次数，先展示原生提示对应的汇总确认，取消则整套零改动。具体次数损失规则仍须核对原生实现，不推断可保留／恢复次数，不自动补充药品。
5. 点击后再次读取并比对快照；装备、角色或世界变化则刷新预览，要求重新点击。执行期间禁止重入，暂停本 MOD 的搜索重建。只操作差异槽位，同一物品两槽互换须规划解开占位的合法顺序；原生互换、临时卸下及活动武器行为确认前，此种计划不可应用，不猜测底层行为。
6. 使用原生装备方法串行执行，每一步读回结果，失败立即停止。提前移除会影响最终类别上限／唯一性的旧饰品或召唤物，再装备目标；任何中间状态也必须合法。药品安排在武器与饰品全部核对成功后处理；若换药部分失败，逐槽显示真实结果，不把原先装备恢复成功等同于药品次数已恢复。每次仅推进少量步骤，遵守游戏线程的 UObject 调用要求，不使用后台线程操作 UObject。
7. 全部读回一致后标记成功，并按原生委托刷新槽位、属性、模型和说明。没有证实原生异步生效时序前，不以函数返回值直接宣称成功。
8. 失败时只对已完成的武器、影之武装、饰品操作尝试原生恢复，并逐项读回。恢复失败要明确列出实际残留装备，保留原快照供用户查看；不能宣称事务原子性，也不改整份存档来兜底。

撤销只在同一角色／存档／世界会话、尚无手动装备变更时可用；撤销前重新检查条件。撤销不涉及药品。勾选换药后，在确认和结果中明确告知药品次数不能由 MOD 撤回。注销、换档、切图、进入演武场或手动改装后清除撤销入口。自定义方案可持久化，撤销快照仅保存在内存。

四、饰品、武器等搜索

在原生装备选择列表上方统一增加搜索框，覆盖主武器、影之武装、饰品、药品；配装面板也复用索引。原生外观、任务物品、商店与升级列表暂不纳入本模块首版。

匹配字段：当前显示名、基础名、铸魂名、各普通打磨名称、原生类型名、原生描述的纯文本；支持诊断用物品 ID。基础／铸魂形态指向同一背包 ID，搜索「黑伤」「黑魔伤」都可找到 Tang，但只显示玩家实际持有的形态；搜索「残破容器」「残破容器·改」也不生成多件物品。

去首尾空白、Unicode NFKC、拉丁字母大小写归一；中文直接子串匹配，空格分词采用 AND。剥除富文本标签但保留文字；动态数值优先使用原生已解析描述，不用占位符冒充数值。不使用正则执行用户输入。首版不做拼音、模糊语义或联网搜索；别名来自两种语言的原生资源及本模块语言文件，不让本地模型翻译。

精确显示名 → 名称前缀 → 名称包含 → 描述包含排序，同级保留原生顺序。类别、子类别筛选与搜索取交集；默认只显示已拥有物品，未获得装备仅在预设详情显示缺件。装备列表搜索是「当前分类的实际可选物品」，配装面板搜索是「预设名、用途与方案内装备文本」，两者不混合成无法直接选装的列表。

搜索框输入约 150ms 去抖；索引在打开页面时建立，物品新增、强化、铸魂、打磨、换语言后增量失效。每帧分批处理索引和行刷新，取消旧查询的工作；页面关闭解绑委托、取消定时器。配置读写异步执行，持续写入合并，使用同目录临时文件原子替换；禁止每按一键写磁盘。

筛选后保留仍然可见的选中 ID，否则移到首项；零结果同时清空旧详情、图标、确认动作和手柄导航目标，不能只把按钮隐藏。清除搜索恢复原生列表与滚动定位。中文输入法合成阶段不执行换装快捷键；输入框焦点优先消费文字／空格／回车，Esc 先清空再退出。手柄复用当前导航和平台文本输入入口；若平台文本输入不可用，仍提供类别筛选，不能假称支持手柄输入汉字。

六、数据契约与完成标准

data/presets.schema.json 描述结构；schemaVersion 升级才修改不兼容结构。data/presets.json 仅保存稳定 ID、顺序、来源、条件和结构化建议，物品显示名通过原生资源获取。locales 两份资源必须键集合一致。preview/apply 使用同一份解析后的计划，不能各自再算一次装备。

当前数据共 22 个唯一预设；主武器／影之武装／药品各有 2 个槽位且分类正确，主武器与影之武装槽位允许 null 表示保留当前；exact 饰品恰为 6 件、同类别不超过 3；所有 ID 来自当前提取数据；所有文案键有中英文值；铸魂条件只引用本套武器；数组顺序的意义明确。阶段配置的目标数量不等于角色已解锁槽数。

后续实现验收场景：缺件与锁槽零改动；实际低等级显示机制缺失；基础名与铸魂名检索同一 ID；同名／打磨名称无重复行；两槽互换、三攻饰品替换、召唤物替换遵守中间状态限制；零搜索结果无旧确认目标；输入法不误触配装；重复打开无委托泄漏；快照变化中止；部分失败如实显示恢复结果；不同语言／不同周目／换档不串配置；换药取消整套零改动。

本次仅做静态数据与文案一致性核对，不新增测试代码，不开展 UI 手动或交互测试；运行时验证保持未完成状态。

七、2026-11-14 用户配装与实现补充

新增炽刃通用技能流、杀气连招套装、破军套装，全部主武器与影之武装槽位为 null，保留玩家自带。杀气连招套装按用户修正移除妙手千钧，只要求其余五件，空余槽位保留合法的已有饰品。破军套装仍按其独立截图保留妙手千钧。截图、来源校验值及用户修订保存在 data/sources。

schemaVersion 2 增加 null 武器槽和 required 饰品模式。required 的所有列出物品必须持有，不像 priority 那样跳过缺件；补入的原有饰品仍须满足解锁槽与每类三件限制。exact 继续要求六件。

当前运行时在原生饰品选择列表接入搜索，在装备页提供预设列表、周目筛选、差异预览、逐步换装、可选药品确认与同页撤销。自定义持久化编辑器及其他装备分类搜索仍为后续设计；需要原生两槽互换或卸下武器的计划会提前阻止。完整兼容边界见 COMPATIBILITY.txt。
